# 企业级多Agent股票分析系统冷启动优化方案

> **副标题**：Hybrid RAG + Evidence Packet 防幻觉体系升级

> **版本**：v2.0

> **日期**：2026-05-31  

> **作者**：Jinhang HE 
>
> **目标**：Phase 1 于 1-2 周内上线，3-4 周达到生产可用级别，彻底解决新股票冷启动幻觉问题，同时保留企业级可靠性、合规性与可观测性。
## 1. 问题背景与根源分析

现有 RAG 防幻觉机制在文档库覆盖的股票上表现优秀；但当目标股票在知识库中完全无信息（冷启动场景）时，系统退化为纯 LLM 生成，幻觉风险激增。

### 1.1 核心痛点

| # | 痛点 | 影响 |
|---|------|------|
| 1 | 检索结果为空 | 无可靠上下文，模型自由发散 |
| 2 | 缺乏实时外部数据 + 结构化事实底座 | 无法区分"不知道"和"不确定" |
| 3 | 知识库更新依赖人工 / 被动触发 | 无法形成自动闭环 |

### 1.2 融合方案目标

最小化改动现有架构，实现：
- **"第一次分析后永久变已知"**：冷启动数据自动沉淀为知识
- **注入 Evidence Packet 机制**：统一事实底座，提升 grounding 能力
## 2. 核心架构升级：Hybrid RAG + Evidence Packet

> **主框架**： Hybrid RAG + Tool-Use  
> **融合精华**： Evidence Packet + 证据充分性检查

### 2.1 改造思路（最小侵入式）

```
现有 RAG 检索（向量 + 关键词）
        │
        ▼
  检索失败判断（满足任一即触发 Tool-Use）：
    ├── 结果为空
    ├── 最高相似度 < 0.65（可调阈值）
    └── 置信度低于预设值
        │
        ▼
  自动触发 Tool-Use（Data Collector / Fetcher Agent）
        │
        ▼
  生成标准化 Evidence Packet（JSON 事实底座）
        │
        ▼
  所有下游 Agent 严格基于 Evidence Packet 分析
        │
        ▼
  Verifier + Critic + Guard 证据充分性检查
        │
        ▼
  异步落库 + 知识闭环
```

### 2.2 推荐企业级数据源（按优先级排序）

| 优先级 | 数据源 | 主要用途 | 优势 |
|:---:|--------|----------|------|
| **高** | Polygon.io / Alpha Vantage / Yahoo Finance | 股价、财报、基本面 | 低成本、实时、结构化强 |
| **高** | HKEX API / SEC EDGAR | 官方公告、财报 PDF | 合规权威 |
| **中** | Bloomberg / Refinitiv / FactSet | 深度研报、新闻、ESG | 机构级准确性 |
| **中** | NewsAPI / Google News + web_search | 最新舆情、突发事件 | 覆盖实时热点 |
| **低** | 网页爬虫（browse_page） | 公司官网、公告 PDF | 补充非结构化数据 |

> **技术实现**：使用 LangGraph / CrewAI / ReAct 让 Agent 自主决策调用 Tool，对现有系统改动极小。
## 3. Evidence Packet（核心融合点）

Data Collector Agent 取证完成后，统一输出以下 JSON 作为所有下游 Agent 的**唯一事实底座**：

```json
{
  "symbol": "NVDA",
  "generated_at": "2026-05-31T20:00:00+08:00",
  "coverage": {
    "market_data": "available",
    "fundamental_data": "available",
    "news_data": "partial",
    "rag_context": "missing",
    "evidence_score": 72
  },
  "market_data": { "..." : "..." },
  "fundamental_data": { "..." : "..." },
  "news": [ "..." ],
  "missing_fields": ["analyst_estimates", "latest_10K_details"],
  "evidence_quality": "medium"
}
```

### 3.1 核心作用

| # | 作用 | 说明 |
|---|------|------|
| 1 | **统一事实底座** | 所有 Agent 基于同一份 Evidence Packet 分析，消除各说各话 |
| 2 | **可校验性** | Verifier / Critic 直接检查证据充分性，无需回溯原始数据 |
| 3 | **按质入库** | 异步落库时仅保留高质量字段，低质量数据不污染知识库 |

## 4. 多Agent协作与幻觉防御升级

### 4.1 新增 / 增强角色

| 角色 | 职责 | 关键输出 |
|------|------|----------|
| **Data Collector Agent** (新增) | 专职 Tool 调用 + 生成 Evidence Packet | 结构化事实底座 |
| **Verifier Agent** (增强) | 跨来源交叉验证（同一指标 ≥2 个来源一致方采纳） | 验证结果 + 可信标记 |
| **Critic Agent** (增强) | 证据充分性检查 + 置信度评分 | Confidence Score + missing_fields 分析 |
| **Guard Agent** (增强) | 最终校验 + 熔断决策 | `is_valid` / `status: "insufficient_evidence"` |

### 4.2 冷启动专属 Guardrail

- 输出最前面**自动添加警示横幅**（见第 5 节）
- 置信度 < 阈值时：**仅输出数据汇总 + 来源 + 缺失清单**，拒绝生成强投资建议

## 6. 企业级生产增强

| 维度 | 方案 |
|------|------|
| **缓存与性能** | Redis 24h 缓存相同 Ticker |
| **异步闭环** | Kafka / RabbitMQ 事件驱动 + 异步落库 |
| **存储分离** | PostgreSQL + TimescaleDB（结构化）+ 向量数据库（非结构化） |
| **可观测性** | 冷启动比例监控、RAGAS / LLM-as-Judge 幻觉检测、用户反馈回路（👎 按钮 → 自动触发重新采集 + 人工 Review） |
| **合规审计** | 完整日志、免责声明、敏感股票强制走 HKEX 官方源 |
| **未来扩展** | Graph RAG、Finance-specific 小模型 Verifier |

## 7. 实施路线图（分阶段落地）

| 阶段 | 时间 | 主要工作 | 预期效果 |
|:---:|:---:|----------|----------|
| **Phase 1** | 1-2 周 | Hybrid RAG + Evidence Packet + Guardrail | 解决 80% 冷启动幻觉 |
| **Phase 2** | 2-4 周 | 自动化入库管道 + 事件驱动闭环 + 报告模板 | "一次分析，永久已知" |
| **Phase 3** | 1-2 月 | 监控仪表盘 + 企业数据源接入 + Graph RAG | 生产级稳定、可审计、可扩展 |
## 8. 总结

| 现有能力 | 本方案升级后 |
|----------|-------------|
| 有资料时防止 LLM 乱说 | **+** 没资料时先取证、结构化事实、再分析 |
| RAG 驱动的事后校验 | **→** 证据驱动的冷启动分析 |

> **最终目标**：构建企业级稳定、可信、可审计的股票分析能力。
