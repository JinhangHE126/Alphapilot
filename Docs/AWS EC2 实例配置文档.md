## 四、模型下载状态与 Qwen2.5 MVP 方案

原计划使用 **Llama 3 Base Model + FinGPT Llama3 LoRA**，但两个模型在申请访问权限时均被拒绝。随后评估过 **FinGPT 官方 Qwen LoRA + Qwen2.5-7B** 方案，但该 LoRA 与 Qwen2.5-7B 的兼容性仍需验证。

为优先服务当前作品集与求职目标，当前决定采用 **纯 `Qwen/Qwen2.5-7B-Instruct`（不加载 LoRA）** 作为 MVP 推理模型，先跑通 `vLLM + FastAPI + LangGraph + RAG` 端到端系统。

### 4.1 原 Llama 方案状态

| 模型类型 | Hugging Face 模型 | 当前状态 | 说明 |
|----------|-------------------|----------|------|
| **Base Model** | `meta-llama/Meta-Llama-3-8B-Instruct` | 申请被拒，无法下载 | gated 受限模型，需要 Meta/Hugging Face 审批许可 |
| **LoRA Adapter** | `FinGPT/fingpt-mt_llama3-8b_lora` | 申请被拒，无法继续使用 | 依赖 Llama 3 base model，当前路线暂停 |

### 4.2 当前采用方案

| 模型类型 | Hugging Face 模型 | 当前状态 | 说明 |
|----------|-------------------|----------|------|
| **Base Model** | `Qwen/Qwen2.5-7B-Instruct` | 准备下载并部署 | 当前 MVP 主模型，优先用于跑通完整项目链路 |
| **LoRA Adapter** | 暂不使用 | 延后评估 | 避免 LoRA 兼容性问题影响 MVP 进度 |

### 4.3 关键技术说明

LoRA adapter 必须和训练时使用的 base model 架构匹配。`FinGPT/fingpt-mt_qwen-7b_lora` 是 FinGPT 官方 Qwen LoRA，但其名称显示更可能对应早期 `Qwen-7B` 系列，而不是 `Qwen2.5-7B-Instruct`。如果现在强行接入 LoRA，可能会引入加载失败、输出质量不稳定或排障成本过高的问题。

因此当前阶段采用 **模型能力与系统架构解耦** 的策略：先用稳定、开放、可部署的 `Qwen/Qwen2.5-7B-Instruct` 跑通完整系统，再把 FinGPT LoRA 或其他金融增强模型作为后续升级项。

| 阶段 | 模型策略 | 目的 |
|------|----------|------|
| MVP 阶段 | 纯 `Qwen/Qwen2.5-7B-Instruct` | 快速跑通云端部署、多 Agent、RAG 与 API 服务 |
| 增强阶段 | 金融 LoRA / FinGPT / 其他金融模型 | 在系统稳定后提升金融问答与投研分析效果 |
| 展示阶段 | 强调系统工程能力 | 面向求职展示完整架构、部署能力、成本控制与可扩展设计 |

### 4.4 vLLM 启动配置建议

在 `g4dn.2xlarge` 的 NVIDIA T4 16GB 显存上，建议先使用保守参数启动，避免因上下文长度过大导致显存不足：

```bash
python -m vllm.entrypoints.openai.api_server \
    --model Qwen/Qwen2.5-7B-Instruct \
    --port 8000 \
    --max-model-len 2048 \
    --gpu-memory-utilization 0.85 \
    --host 0.0.0.0
```

如果显存仍然不足，可继续降低 `--max-model-len`，或后续评估量化部署方案。MVP 阶段优先保证服务稳定可访问。

### 4.5 当前结论

当前部署环境已基本跑通，原 Llama 3 路线因模型授权被拒暂停。下一步优先使用 **纯 `Qwen/Qwen2.5-7B-Instruct`** 跑通 AlphaPilot 端到端链路；FinGPT LoRA 或其他金融增强模型作为后续优化项，不再阻塞当前 MVP 部署。
