1. 架构总览

AlphaPilot 采用 "Builder 统一采集证据 → Agent 只消费证据" 的 evidence-first 架构，将 RAG 和结构化事实缓存融合为一条多级数据聚合管道。

START │ ▼ ┌──────────────────────────────────────────────────────────┐ │ Evidence Packet Builder (EPB) │ │ │ │ Layer 1: RAG 语义检索 (FAISS) │ │ ├── 向量检索历史相似分析记录 │ │ ├── Symbol 匹配过滤 (同名公司干扰排除) │ │ └── 相似度阈值门控 (0.55) │ │ │ │ Layer 2: Fact Store 结构缓存 (SQLite) │ │ ├── 按 field 级读写，TTL 分层过期 │ │ ├── market_data: 5min → fundamental: 180d │ │ └── 高优先级回填 collector 缺口 │ │ │ │ Layer 3: Live Data Collectors │ │ ├── Market (yfinance, AKShare, etc.) │ │ ├── Fundamental / News / Filing / HKEX │ │ │ │ Merge → Conflict Detection → Scoring → Ingestion │ └──────────────────────┬───────────────────────────────────┘ │ EvidencePacket (JSON) ▼ ┌──────────────────────────────────────────────────────────┐ │ Orchestrator │ │ insufficient → Guard → END │ │ limited → Market/Fund/News → Strategy → Risk │ │ full → + Debate + Portfolio + Backtest + Recommend │ └──────────────────────┬───────────────────────────────────┘ ▼ All downstream agents (tools=[], 只读 evidence_packet + messages)

2. RAG 层分析

2.1 技术选型

组件技术源文件
嵌入模型all-MiniLM-L6-v2 (HuggingFace, CPU 推理)rag/retriever.py
向量库FAISS (本地持久化)rag/retriever.py
辅助向量库ChromaDB + Google Gemini Embeddingrag/vectorstore.py

2.2 核心设计点

(a) 双层 Embedding 加载策略

  • 优先 local_files_only=True — 离线可用，无网络依赖
  • 失败后降级为联网下载，保证系统韧性

(b) Over-fetch + 过期过滤

fetch_k = max(k * 3, k + 10) 过度检索后按 TTL 过滤过期文档，再截断到 k，避免过期文档挤占有效结果位置。

(c) Distance → Similarity 统一转换

FAISS 返回 L2 distance（越小越相关），系统统一转为 similarity = 1 / (1 + distance)，下游消费者只需关注 similarity。

(d) doc_id 去重 + Symbol 匹配过滤

  • 扫描现有索引的 doc_id，相同自动跳过，避免向量库膨胀
  • symbol.upper() 强制匹配过滤，排除跨公司干扰

2.3 冷启动判定逻辑

if Fact Store 命中 (≥3 active facts + fundamentals): is_cold_start = False → 直接复用缓存 + 实时刷新 elif RAG top similarity < 0.55 or 无结构化 metadata: is_cold_start = True → 触发 live data collector else: is_cold_start = False → RAG 文本上下文足够

3. Evidence Packet 层分析

3.1 数据模型

模型用途关键字段
Fact 字段级事实 field, value, unit, period, source, as_of_date, confidence, confidence_tier
MissingField 缺失标记 field, reason, substitute（替代字段）
Conflict 跨源冲突 field, values, sources, resolution
Coverage 数据覆盖矩阵 rag_context, market_data, fundamental_data, news_data, filings
EvidencePacket 顶层证据包 以上聚合 + evidence_score + allowed_output_level

3.2 三级置信度体系

等级权重来源标记
MACHINE 1.0 直接 API 返回值 (price, PE, volume) [✓]
LLM_EXTRACTED 0.5 LLM 从文本中提取 (news headline, filing text) [~]
LLM_INFERRED 0.2 LLM 推理得出 (sector classification) [?]

3.3 Evidence Score 计算公式

evidence_score = source_diversity × 0.25 ← 来源多样性（加权计算 MACHINE 源优先级） + recency × 0.25 ← 数据时效性 (≤1天:100, ≤7天:80, ≤30天:60, ...) + completeness × 0.30 ← 字段完整性（加权期望字段数） + field_confidence × 0.20 ← 字段级平均置信度 (tier-weighted)

3.4 五级输出门控

条件Output LevelAgent 行为
0 facts 或 cold_start + 无 machine fact INSUFFICIENT_EVIDENCE 直接 Guard → END，不执行任何分析
score < 30 INSUFFICIENT_EVIDENCE 同上
score < 50 DATA_SUMMARY_ONLY 仅返回数据摘要，禁止投资建议
关键字段缺失 ≥ 2 LIMITED_ANALYSIS Market/Fund/News → Strategy → Risk → Guard，无 recommendation
关键字段有替代 + score ≥ 85 + 无冲突 FULL_ANALYSIS 完整 14-agent 管线
关键字段有替代 + score ≥ 80 LIMITED_ANALYSIS_PARTIAL 允许分析但标注数据质量
其他 LIMITED_ANALYSIS 降级分析

3.5 Substitute 机制

当某字段不可直接获取时，系统尝试替代字段，不完全阻断分析但标注数据质量限制：

FIELD_SUBSTITUTES = { "revenue_growth_yoy": ["revenue", "revenue_ttm"], "eps_growth_yoy": ["eps", "eps_diluted"], }

3.6 跨源冲突检测

  • 同一 field 多个数值 fact 且来源不同 → 计算偏差率
  • 偏差超阈值 (current_price: 2%, pe_ratio: 10%, growth: 5%) → 标记冲突
  • 有官方来源 (SEC_EDGAR/HKEX) → official_source_preferred
  • 仅有第三方 → marked_unresolved

4. 动态事实缓存（两层存储）

4.1 Fact Store (SQLite 结构化缓存)

特性实现
TTL 分层market_data: 5min, fundamental: 180d, news: 30d, filings: ∞
去重策略payload_hash 比对，相同数据不重复写入，旧版本标记 superseded
查询接口get_active_facts(symbol) 自动过滤过期记录
覆盖检查has_coverage(symbol, fields) 决定是否触发冷启动

4.2 FAISS 动态事实缓存

  • EPB 构造完 Evidence Packet 后自动调用 upsert_packet
  • 过滤条件：evidence_score ≥ 50 且 confidence_tier ≠ LLM_INFERRED
  • 每个 fact 转为 "field: value (source: xxx, date: yyy)" 文本 + metadata 写入 FAISS
  • 同时写入 Fact Store (SQLite) 和 Document Store (JSON 全量备份)

4.3 Escape Pod 降级机制

Collectors 全失败 + RAG 缓存命中 → 降级为 RAG-only (ESCAPE POD DEGRADE) Collectors 全失败 + RAG 无缓存 → 直接拒绝，返回用户友好提示 (ESCAPE POD REJECT)

5. Guard Layer（硬规则校验）

Guard Agent 实现了确定性输出门控，不经过 LLM，确保校验本身不会产生幻觉。

校验维度规则方法
Symbol 错配 packet symbol ≠ state symbol，或 RAG 引用其他股票 _detect_symbol_mismatch
证据不足熔断 INSUFFICIENT_EVIDENCE → 直接拒绝 determine_output_level
违规投资建议 限级输出中出现 "建议买入" / "target price" 等关键词 Keyword match
无据声明 输出中提到某字段但 Evidence Packet 无对应 fact _find_ungrounded_claims
数值溯源 数值字段输出值需在 fact variants 中可匹配 _number_variants
目标价禁止 任何时候禁止输出 target price / 目标价 / 介入点 硬规则绝对禁止

5.1 Guard 重试机制

  • 硬失败 (evidence-level)：直接 END，不回退。例如 Symbol 错配、证据包损坏
  • 软失败 (output-level)：增加 guard_retry_count，校正后回退到 Strategy Agent 重跑，上限 2 次

6. Agent 消费 Evidence Packet 的方式

所有下游 Agent（Market, Fundamental, News, Bull, Bear, Strategy, Risk）均采用只读模式：

tools=[] ← 不调用任何外部工具 prompt ≈ "Read the Evidence Packet section in messages. Base everything strictly on Evidence Packet facts. NEVER fabricate data not present."

Evidence Packet 通过 render_packet_for_agent 渲染为系统消息注入 messages，Agent 只能消费预验证的事实。注入的严格规则包括：

  • [✓] = MACHINE 事实（高置信度）
  • [~] = LLM_EXTRACTED（中置信度）
  • [?] = LLM_INFERRED（低置信度，仅供参考）
  • Missing Data 区域明确标注 "DO NOT fabricate"
  • 禁止输出 target price / 目标价 / 建议买卖

6.1 Bull vs Bear 辩论子图

debate_stage (子图) ├── 入口检查: 证据不足 → END（跳过辩论） ├── bull_researcher → bear_researcher │ ↑ │ │ │ rounds < 2? │ │ │ YES → 回到 Bull │ │ │ NO → END │ │ └──────────────────┘ ▼ strategy_expert (消费辩论历史 + 上游输出)
  • 双方消费相同的 Evidence Packet 和上游输出
  • 每轮 Bull 先发言、Bear 反驳，最多 2 轮
  • Strategy Agent 权重：Market 25% + Fundamental 35% + News 15% + Debate 25%

7. 设计亮点总结

维度设计决策解决问题
解耦采集与推理 Builder 统一采集 → Agent 只读消费 消除 Agent 各自调用工具导致的 fact 不一致、重复调用
三级置信度 Machine / LLM_Extracted / LLM_Inferred 下游 Agent 可区分硬数据和推断，降低幻觉传播
五级输出门控 按证据分数动态路由 数据不足时拒答或降级，而非强行生成不可靠分析
多层缓存策略 RAG 语义缓存 + Fact Store 结构化缓存 + Document Store 全量备份 兼顾语义检索灵活性和结构化查询效率
Substitute 机制 增长率缺失 → 绝对值替代 不完全阻断分析，但标注数据质量限制
跨源冲突检测 同一字段多源数值偏差超阈值 → 标记冲突 / 官方优先 避免 Agent 基于矛盾数据推理
Escape Pod 全故障场景的优雅降级 不会因网络/API 问题崩溃，有兜底响应
Guard 硬规则 确定性校验，不经过 LLM Guard 本身不会幻觉，熔断可靠
