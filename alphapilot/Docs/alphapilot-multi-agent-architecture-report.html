Evidence-first LangGraph orchestration Zero-tool specialist agents Message-centric state

Executive Summary

AlphaPilot 当前更像一个证据驱动的金融分析流水线，而不是自由协作型 agent swarm。 这个取舍适合金融场景：先集中构造可信 Evidence Packet，再让各专家 agent 在证据边界内生成输出， 最后由 Guard 做确定性事实和权限校验。

Output Level 判定逻辑

系统不是只看总分，还会检查 facts 是否为空、冷启动是否有 machine facts、critical fields 是否缺失、 substitute 是否可接受，以及是否存在 conflicts。最终输出等级包括 insufficient_evidence、data_summary_only、 limited_analysis、limited_analysis_partial 和 full_analysis。

7. Top Insights

Strengths

Evidence-first 架构：数据采集和事实边界集中化，agent 不直接拿工具，明显降低金融分析场景中的幻觉面。

Deterministic Orchestration：路由由 output level 和 executed agents 控制，排查路径比 LLM supervisor 简单。

Hard-rule Guard：Guard 不依赖 LLM 判断核心安全性，适合金融场景的可审计要求。

Risks

messages 过载：多数 agent 返回 messages，而 GraphState 中的结构化字段未充分使用。

策略边界不完全一致：部分 prompt 禁止建议，另一些 agent 仍输出 position size、stop loss，Guard 需要继续承担协调压力。

Evidence Builder 复杂度高：RAG、Fact Store、collector、fallback 和 score 逻辑集中在 workflow.py，后续维护成本会上升。

8. Recommended Next Moves

Priority Move Expected Impact
High 拆分 Evidence Builder 将 RAG 匹配、Fact Store merge、collector merge、score 计算拆成独立模块并补单测。
High 让 agent 写结构化 state 字段 例如 market_data、risk_assessment、backtest_metrics，减少后续 agent 从 messages 反向解析。
Medium 统一投资建议权限模型 明确哪些 output level 允许 position sizing、stop loss、personalized action plan，避免 prompt 互相拉扯。
Medium 增强 Guard 的引用级检查 从 final message 扩展到每个 agent 输出，记录 issue 所属 agent 与对应 field。
Medium 为路由表做 golden tests 覆盖每个 output level、guard soft/hard failure、alert/optimization/personalized 分支。
Low 把 provider health 暴露到监控 registry 已有 cooldown 和 failure_count，可进入 metrics/reporting 形成数据源可靠性视图。
